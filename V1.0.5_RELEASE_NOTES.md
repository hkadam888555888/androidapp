# My Adaptive Routine v1.0.5 — source hardening candidate

**Status: audit candidate only; not production-verified.**

## Fixes

- Fixed recurrence handling: an explicitly empty weekly/custom weekday list no longer silently becomes a daily schedule. Daily recurrence still means every weekday, and legacy rows without the weekday array retain a compatibility fallback.
- Aligned the task-store partial-habit guard with the domain's `minimum_value` outcome policy.
- Reject invalid calendar dates at the planning-service boundary.
- Tightened backup validation: habit targets and logged quantities/durations must be positive, logged values cannot be negative, weekday arrays must contain unique integers in 0–6, time-pattern rates must stay in 0–1, buffer percentage follows the same 0–90 rule as settings, task estimate bounds must be consistent, active/availability date bounds must be ordered, and stores introduced after the declared historical schema are rejected.
- Added regression tests and source-audit checks for these cases.

## Data compatibility

No IndexedDB record shape or object store changed. Database schema remains v9; app/package version is 1.0.5.

## Verification boundary

Source-level audit and a dependency-free compatibility harness are not equivalent to the official Vitest runner. The npm registry is unavailable in this environment and the project has no committed lockfile or installed project dependencies. A real production build, official unit/coverage/lint/audit checks, Playwright browser tests, migration/restore browser tests, and Android device tests must still run in a network-enabled environment. Do not label this archive production-ready or Android-ready.
